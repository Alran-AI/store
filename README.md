# Alran store

A curated catalogue of Skills and Plugins for Alran Code. Nothing here is written by us: every Skill is an
**unmodified copy** from an open-source project or a platform vendor's own skills repository, at a pinned
commit, under its own licence (see `THIRD_PARTY_NOTICES.md`; each folder also carries `LICENSE.txt` and
`SOURCE.md`).

| Source | Licence | Skills |
| --- | --- | ---: |
| [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills): engineering workflow | MIT | 21 |
| [cloudflare/skills](https://github.com/cloudflare/skills) | Apache-2.0 | 13 |
| [firebase/agent-skills](https://github.com/firebase/agent-skills) | Apache-2.0 | 10 |
| [supabase/agent-skills](https://github.com/supabase/agent-skills) | MIT | 2 |
| [stripe/ai](https://github.com/stripe/ai) | MIT | 3 |
| [expo/skills](https://github.com/expo/skills) | MIT | 10 |

It builds into a store that Alran Code reads (`docs/store.md` in the Alran Code repository): 6 Plugins (one per
source; the 21 engineering-workflow Skills are only offered inside their Plugin, because they link to shared
checklists the Plugin carries) and 38 individually installable Skills.

```sh
alran plugin marketplace add /path/to/alran-store/store     # or host store/ anywhere and add its URL
alran plugin search cloudflare
alran plugin install engineering-workflow
alran skills install wrangler
```

**Not published.** This repository has no remote and Alran Code has no built-in default store. Host the `store/`
folder on any static host (or a Git host that serves raw files) and give its address to
`alran plugin marketplace add`, or set `ALRAN_STORE_URL`.

## Layout

| Path | What |
| --- | --- |
| `sources.json` | The pinned sources and the exact Skills taken from each |
| `scripts/vendor.mjs` | Copies those Skills from local clones, refusing anything that breaks the rules below |
| `skills/<source>/<name>/` | Vendored Skills (unmodified, plus `LICENSE.txt` and `SOURCE.md`) |
| `shared/<source>/` | Shared files a source's Skills link to (carried inside that source's Plugin) |
| `store/store.config.json` | Store name, group names, titles, versions, and the Plugin bundles |
| `store/icons/` | Plugin icons, generated by `scripts/gen-icons.mjs` |
| `store/index.json`, `store/archives/` | Generated by the store builder; commit the result |
| `THIRD_PARTY_NOTICES.md` | Generated: sources, commits, licence texts |

## Update or add a source

```sh
git clone <repo> <work>/<clone>      # then check out the commit you want; put it in sources.json
node scripts/vendor.mjs --work <work>
node <alran-code>/tools/store/build-store.mjs --source .          # writes ./store
node <alran-code>/tools/store/build-store.mjs --source . --check  # exit 1 if ./store is stale
```

Versions are `<commit date>+<short commit>` (SemVer: no zero padding), set per source in `store/store.config.json`
(`vendor.mjs` prints the values); an update is recognised by the content digest changing.

## What is let in, and what is not

`vendor.mjs` refuses a Skill that has any script or executable (`.sh`, `.py`, `.js`, `.ts` …), any file that
is not plain text, a symlink, a file name a portable archive cannot hold, a `SKILL.md` that does not name its
folder, or a clone that is not at the pinned commit. Beyond that, each Skill was checked for links that leave
its folder (they must resolve inside the installed Plugin or Skill folder), hidden or invisible characters,
HTML comments, data URIs, long encoded blobs and `curl | sh` style commands. The Skills run no code of their
own; what an agent does with their text goes through Alran's normal permissions.

Left out on purpose (the reasons are facts about the source, not quality judgements):

- Skills with scripts: `constraint-driven-development`, `idea-refine` (addyosmani), `turnstile-spin`
  (Cloudflare), `xcode-project-setup` (Firebase), `eas-workflows`, `expo-ui` (Expo), the Hugging Face skills.
- Skills that pipe a download into a shell or decode blobs: `stripe-directory`, `stripe-projects`,
  `expo-examples`.
- `firebase-data-connect-basics`: its `SKILL.md` names a different skill than its folder, so it would need an edit.
- [obra/superpowers](https://github.com/obra/superpowers) (MIT): its Skills call each other as
  `superpowers:<name>` and overlap with the engineering workflow set; it belongs in as one complete Plugin
  under its own name, which needs its scripts and hook reviewed first.
- [anthropics/knowledge-work-plugins](https://github.com/anthropics/knowledge-work-plugins) (Apache-2.0): its
  Skills assume MCP connectors for Slack, Linear and similar, which are not set up here.
- [openai/skills](https://github.com/openai/skills) and [anthropics/skills](https://github.com/anthropics/skills):
  licensed skill by skill (the document skills of the latter are not open); each would need its own check.
- [vercel-labs/agent-skills](https://github.com/vercel-labs/agent-skills): no licence files, so it cannot be
  redistributed.

Whoever publishes a store is responsible for the licences of what is in it. The scripts and configuration in this
repository have no licence file yet; that is for the owner to choose.
